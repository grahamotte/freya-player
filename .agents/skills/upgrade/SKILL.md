# Upgrade

Use this skill when the user asks to update dependencies, bump versions, upgrade everything, or refresh project tool versions.

## Scope

Update all of these, unless the user narrows the request:

1. The `[tools]` table in `mise.toml`
2. `frontend/package.json`
3. every Ruby `Gemfile`
4. every Ruby `*.gemspec`

Prefer latest versions even when they are major upgrades. Pin all direct dependency declarations to exact versions. Lockfiles must be generated by package manager commands, not edited directly.

## Workflow

1. Inspect the current diff first and preserve unrelated user changes.
2. Update the `[tools]` table in `mise.toml`:
   - For each tool, use `mise latest <tool>` or the appropriate `mise latest <tool>@<major>` when staying on the same major/minor family is intentional.
   - Install or verify each changed tool with `mise install <tool>@<version>`.
   - Do not disable artifact verification to make an old version work. If a tool install fails because attestations are missing, choose a newer version that verifies.
3. Update frontend dependencies:
   - Use `pnpm`, not npm or Bun.
   - Run from `frontend`.
   - Use latest eligible versions, including majors, while keeping the 7-day release-age hardening: `pnpm update --latest --save-exact --config.minimum-release-age=10080`.
   - Ensure every dependency and devDependency in `frontend/package.json` is exact pinned, for example `"react": "19.2.6"`, with no `^` or `~`.
   - Keep `packageManager` pinned to the `mise.toml` pnpm version.
   - Let pnpm generate `pnpm-lock.yaml`; do not edit it by hand.
   - Confirm `pnpm outdated --config.minimum-release-age=10080` reports nothing outdated.
4. Update Ruby dependencies:
   - For each directory with a `Gemfile`, run `mise exec -- bundle update`.
   - Pin every direct `gem` declaration in `Gemfile` to the resolved lockfile version.
   - Pin every `spec.add_dependency` and `spec.add_development_dependency` declaration in `*.gemspec` to the resolved lockfile version.
   - Preserve options such as `path:`, `require: false`, and `platforms:`.
   - Path gems should be pinned to their local version and keep the path option, for example `gem "path", "0.0.0", path: "../gems/path"`.
   - Regenerate `Gemfile.lock` files with checksums using `mise exec -- bundle lock --add-checksums`; do not edit lockfiles by hand.
   - Treat Bundler `CHECKSUMS` sections as required supply-chain hardening. They must not be lost during an update.
   - Verify every `Gemfile.lock` still has a `CHECKSUMS` section after regeneration.
   - Confirm `bundle outdated` reports `Bundle up to date!` in every Ruby package directory.
5. Search for stale tool/package-manager references:
   - No Bun references should remain unless the user explicitly asks for them.
   - No removed dependency names should remain outside generated or vendored files.
6. Run `mise test` after all changes.

## Notes

- The repo intentionally uses pnpm hardening in `pnpm-workspace.yaml`; do not remove `minimumReleaseAge` or `blockExoticSubdeps`. Frontend pnpm commands should use `--config.minimum-release-age=10080` when specifying the setting explicitly.
- The repo intentionally uses Bundler lockfile checksums for gem integrity; keep them in every `Gemfile.lock`.
- For deploy compatibility, prefer versions that install cleanly through mise on Linux with verification enabled.
- If a major update emits upgrade notes, report the note briefly in the final response.
